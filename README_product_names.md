# Товары: правильные названия UA/RU, веб-проверка и раскладка по категориям Хорошоп

Два скрипта:

| Скрипт               | Что делает                                                                                                            |
|----------------------|-----------------------------------------------------------------------------------------------------------------------|
| `product_names.py`   | Берёт список товаров (CSV/JSON), через Claude API формирует грамотные названия и категории на украинском и русском, при желании проверяет написание брендов/моделей через веб-поиск, сортирует и сохраняет результат. |
| `horoshop_sync.py`   | Связка с сайтом на Хорошоп через его API: выгружает дерево разделов и товары, прогоняет их через Claude с подбором правильной категории/подкатегории/подподкатегории и загружает названия и разделы обратно. |

Внутренний модуль `horoshop_client.py` реализует API Хорошоп (`auth`, `pages/export`, `catalog/export`, `catalog/import`)
по официальной документации: https://horoshop.notion.site/api-doc.

## Самый простой запуск (меню)

```bash
python run.py          # Windows: двойной клик по start.bat, macOS/Linux: ./start.sh
```

При первом запуске скрипт спросит ключ Claude API, домен сайта, логин и пароль API Хорошоп и сохранит их
в файл `.env` рядом со скриптом (он в `.gitignore`, в репозиторий не попадает; образец — `.env.example`).
Дальше пункты меню повторяют шаги ниже: разделы → товары → обработка через Claude → предпросмотр → загрузка.
Пункт 7 проверяет установку на примере без ключей.

## Установка (ручной вариант)

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...      # ключ из https://platform.claude.com
```

Для Хорошоп дополнительно (логин и пароль API-администратора создаются в админпанели: Налаштування → Адміни):

```bash
export HOROSHOP_DOMAIN=myshop.com.ua
export HOROSHOP_LOGIN=api_user
export HOROSHOP_PASSWORD='...'
```

Пароль передаётся только через переменную окружения, в командной строке и в файлах он не хранится.
Доступ к API Хорошоп включает техподдержка платформы для каждого магазина отдельно.

## Сценарий для Хорошоп (4 шага)

```bash
# 1. Дерево разделов сайта -> categories.json (и печать дерева в консоль)
python horoshop_sync.py categories --out categories.json

# 2. Все товары -> products.csv (артикул, названия ua/ru, текущий раздел, бренд, цена)
python horoshop_sync.py export --out products.csv

# 3. Claude: новые названия ua/ru + подходящий раздел из дерева -> review.csv
#    --web-check включает проверку написания брендов и моделей через интернет
#    --limit 30 — попробовать на первых 30 товарах
python horoshop_sync.py process --in products.csv --categories categories.json --out review.csv --web-check

# 4. Проверить review.csv глазами, при необходимости поправить, затем загрузить на сайт
python horoshop_sync.py apply --in review.csv --dry-run    # показать payload catalog/import
python horoshop_sync.py apply --in review.csv --yes        # отправить
```

Файл `review.csv` содержит исходные данные плюс колонки:

| Колонка            | Содержимое                                                                        |
|--------------------|-----------------------------------------------------------------------------------|
| `name_uk`, `name_ru` | новые названия                                                                 |
| `category_id`      | id выбранного раздела (самый глубокий подходящий, 0 — не подобран)                |
| `category_path`, `category_path_ru` | полный путь раздела на двух языках                               |
| `category_changed` | `yes`, если раздел отличается от текущего на сайте                                |
| `comment`          | замечания модели: сомнения, предложения создать раздел, результат веб-проверки    |
| `apply`            | `yes` — строка уйдёт в `apply`; очистите ячейку, чтобы пропустить товар           |

`apply` обновляет у товара `title.ua`, `title.ru` и `parent.id` (по артикулу). Флаги `--no-titles` / `--no-categories`
ограничивают изменения. Без `--yes` команда только показывает, что будет отправлено.

Шаг 3 можно запускать и без шагов 1–2: если `--in` не указан, товары и разделы выгружаются с сайта напрямую.

### Работа с одним разделом (`--root-id`)

В репозитории уже лежит `categories.json` с деревом сайта soundsgood.com.ua (1586 разделов, корень каталога id 97).
Для большого каталога обрабатывайте разделы по очереди: `--root-id` берёт только указанный раздел и его подразделы,
модель видит короткое дерево, а товары из других разделов отбрасываются (`--all-products` отключает отбор).

```bash
# только «Клавішні інструменти» (id 1256) и 54 его подраздела
python horoshop_sync.py process --in products.csv --root-id 1256 --out review_keyboards.csv --web-check
```

Файл дерева может быть в любом из форматов: `{"pages": [...]}` из pages/export, `{"catalog": [...]}` с `parentId`,
список или вложенное дерево с `children`.

## Прайс поставщика: новые товары с правильными названиями и разделами

Для файла поставщика (xlsx/csv) есть отдельная команда. Она сама находит строку с заголовками (даже если выше
шапка с реквизитами), определяет колонки с названием, артикулом, брендом, ценой и категорией, понимает строки-заголовки
групп внутри таблицы («Синтезатори», «Цифрові піаніно» и т.п.) и использует их как подсказку для раздела.

```bash
python horoshop_sync.py supplier --in price.xlsx --root-id 1256 --web-check --out review_supplier.csv
python horoshop_sync.py apply --in review_supplier.csv --create --dry-run   # что будет создано
python horoshop_sync.py apply --in review_supplier.csv --create --yes       # создать товары на сайте
```

В меню `run.py` это пункты 9 и 10. Колонки можно задать вручную: `--name-col`, `--article-col`, `--brand-col`,
`--price-col`, `--category-col`, лист Excel — `--sheet`, строку заголовков — `--header-row`.
Результат `review_supplier.csv` отсортирован по разделу и названию; `apply --create` создаёт товар с артикулом,
названиями ua/ru, разделом, брендом и ценой, но только для строк с `apply=yes`, у которых подобран раздел.
Пример прайса: `examples/supplier_price_sample.xlsx`.

## Самостоятельное использование product_names.py

```bash
# CSV -> CSV, сортировка по умолчанию: категория (uk), затем название (uk)
python product_names.py --input examples/products_sample.csv --output products_sorted.csv

# с веб-проверкой написания и подбором раздела по дереву Хорошоп
python product_names.py -i products.csv -o out.csv --web-check --categories categories.json

# JSON -> JSON, сортировка по русской категории, затем по цене по убыванию
python product_names.py -i examples/products_sample.json -o out.json --sort-by "category_ru,-price"

# Без обращения к API: только очистка названий и сортировка
python product_names.py -i products.csv -o out.csv --offline
```

Если первое поле сортировки начинается с `-`, пишите через `=`: `--sort-by=-price`.

### Входной файл

CSV (разделитель определяется автоматически) или JSON (список объектов либо объект с ключом `products` / `items` / `data`).
Колонки определяются автоматически по названиям или задаются явно:

| Данные    | Автоопределение (без учёта регистра)                         | Опция            |
|-----------|---------------------------------------------------------------|------------------|
| название  | name, title, product, назва, название, наименование, товар    | `--name-col`     |
| категория | category, категорія, категория, група, группа, раздел, розділ | `--category-col` |
| бренд     | brand, бренд, виробник, производитель, manufacturer           | `--brand-col`    |
| цена      | price, ціна, цена, стоимость, вартість                        | `--price-col`    |

Остальные колонки сохраняются без изменений. К каждому товару добавляются `name_uk`, `name_ru`, `category_uk`,
`category_ru`, `brand`, `category_id`, `category_path`, `comment`. CSV пишется в UTF-8 с BOM для Excel.

### Правила, по которым модель формирует названия

Заданы в `SYSTEM_PROMPT` внутри `product_names.py`, их можно править под свой каталог:

- структура «Тип товара Бренд Модель, характеристики» (Смартфон Samsung Galaxy A55 8/256 ГБ, чёрный);
- бренды и модели не транслитерируются и не переводятся;
- единицы измерения через пробел (500 мл, 1,5 л), кавычки «ёлочки»;
- убирается мусор («АКЦИЯ», «NEW», коды поставщика, лишние пробелы);
- исправляются орфография и грамматика, в русском используется «ё», в украинском — ґ, є, і, ї, апостроф;
- характеристики, которых нет в исходном названии, не придумываются.

### Проверка написания через интернет (`--web-check`)

В запрос добавляется серверный инструмент Claude `web_search`: модель сама ищет официальное написание бренда,
серии и модели там, где есть сомнение (`--max-searches` ограничивает число поисков на пакет). Если API не примет
веб-поиск вместе со строгой JSON-схемой, скрипт автоматически переходит на двухэтапный режим: сначала
поиск и заметки, затем формирование ответа по схеме. Веб-поиск оплачивается отдельно по тарифам Claude API.

### Сортировка

`--sort-by` принимает поля через запятую, префикс `-` — по убыванию. Поля с суффиксом `_ru` сортируются по русскому
алфавиту, остальные текстовые — по украинскому (Г < Ґ, Е < Є, И < І < Ї < Й). Числа внутри строк сравниваются как числа
(A2 < A10), регистр не учитывается, латиница идёт после кириллицы. `price` понимает «13 999», «1 299,50 грн», «1,299.50».

### Параметры Claude API

| Опция           | По умолчанию                 | Описание                                                        |
|-----------------|------------------------------|-----------------------------------------------------------------|
| `--model`       | `claude-opus-5-5`            | модель Claude                                                   |
| `--effort`      | `medium`                     | глубина рассуждений: low / medium / high / xhigh / max          |
| `--batch-size`  | 20                           | товаров в одном запросе                                         |
| `--workers`     | 2                            | параллельных запросов к API                                     |
| `--cache`       | `.product_names_cache.json`  | кэш ответов; смена дерева разделов или режима сбрасывает его    |
| `--no-fallback` |                              | отключить серверный fallback на запасную модель при отказе      |

Ответ принимается только в строгой JSON-схеме, дерево разделов и правила кэшируются на стороне API
(prompt caching), id раздела проверяется по дереву: несуществующий id заменяется на 0 с пометкой в `comment`.

## Тесты

```bash
pip install pytest
pytest -q
```

Тесты не ходят в сеть: Claude API и API Хорошоп подменяются заглушками. Проверяются очистка названий, порядок
кириллицы, пакетная обработка, кэш, веб-проверка (включая двухэтапный режим и `pause_turn`), построение дерева
разделов, пагинация экспорта, сборка payload для импорта и CLI.

## Использование как библиотеки

```python
from pathlib import Path
from horoshop_client import HoroshopClient, flatten_product
from product_names import process_products, sort_products

client = HoroshopClient.from_env()
tree = client.export_category_tree()
rows = [flatten_product(p) for p in client.export_all_products()]
rows = process_products(rows, name_col="title_ua", category_col="parent", brand_col="brand",
                        web_check=True, category_tree=tree)
rows = sort_products(rows, "category_path,name_uk")
```
